SMTP Send Email — Documentation

Complete guide — configuration, examples, testing and troubleshooting.

What it does

Send messages via an SMTP server using the module inputs and credentials.

Recommended

Port 587 (STARTTLS). Use App Passwords if 2FA is enabled.

Before you start

Have SMTP host, port, username and password ready; confirm outbound port access.

Overview Fields Examples Test Troubleshoot FAQ

Overview

The SMTP Send Email module enables workflows to send emails via any SMTP-compliant mail server. Supports HTML/plain text via a rich-text editor.

Fields (explained)

From Email (required)
Sender address — match SMTP account for best deliverability.
To Email (required)
Recipient address. Multiple recipients: separate by comma if supported.
Subject
Message subject.
Body
Rich-text/HTML supported. Test across email clients.
SMTP Host
e.g., smtp.gmail.com.
SMTP Port
587 (STARTTLS recommended); 465 for SSL.
SMTP Username
Login, typically full email address.
SMTP Password
Password or App Password (MFA). Use secrets manager if available.

Examples

Gmail 
SMTP Host: smtp.gmail.com
SMTP Port: 587
SMTP Username: your.email@gmail.com
SMTP Password: <app-password>

Google requires App Password if 2FA is active. Use STARTTLS on 587.

Office365 / Outlook 
SMTP Host: smtp.office365.com
SMTP Port: 587
SMTP Username: user@domain.com
SMTP Password: <password or app-password>

Some orgs restrict SMTP — confirm with admin.

Test & Execute

  1. Fill required fields and save.
  2. Click Save & Execute to send a test email.
  3. Check inbox & spam, inspect transaction logs for SMTP responses.

Troubleshooting

Common errors
  • Authentication failed (535) — verify credentials or use App Password.
  • Connection timed out — check host, port and firewall.
  • Relay denied — ensure server allows relay for the user.
Deliverability
  • Set SPF and DKIM records for sending domain.
  • Use consistent From addresses and avoid spammy content.
  • For bulk sends, use a transactional provider (SendGrid, SES, Mailgun).

FAQ

Can I attach files?
Attachments available if module UI supports file input or mapping. Otherwise use storage-to-email steps.
How many emails can I send?
Provider limits apply. Use a transactional service for larger volumes.
How to debug failed sends?
Collect SMTP error, timestamp and recipient; check logs and enable verbose logging if possible.

Send Outlook Email

Step-by-step configuration, field explanations, examples, troubleshooting tips, and automation samples for sending emails via Microsoft 365 / Outlook (Graph API).

What it does

Sends messages using Outlook / Microsoft Graph API or SMTP for Microsoft 365 mailboxes.

Recommended

Use Graph API (OAuth) with Mail.Send scope. Store secrets securely.

Before you start

Register Azure app, obtain Tenant/Client IDs and secret, grant Mail.Send consent.

Overview

The Send Outlook Email module enables workflows to send emails from Microsoft 365 mailboxes. It supports HTML/plain text bodies, attachments, and can use Microsoft Graph API (recommended) or SMTP where necessary.

Fields (explained)

User Email (required)

The Microsoft 365 mailbox that will send the message. Example: john.doe@company.com.

  • Ensure the mailbox exists and is licensed.
  • If using Graph API, the app needs Mail.Send permission.

To Email (required)

Recipient address. Supports multiple recipients separated by commas when the platform maps them correctly. 

alice@company.com, bob@company.com

Invalid addresses may cause bounces — validate when possible.

Subject (required)

The subject line displayed in the recipient's inbox. Keep concise (70 chars) and avoid spammy words.

Body (HTML / Plain text)

Use the rich editor to compose HTML or paste plain text. Include a plain-text fallback for better deliverability. 

<h1>Hello</h1><p>This is a test.</p>

Tenant ID / Client ID / Client Secret (required for Graph API)

These values authenticate your app with Azure AD. Obtain them from Azure Portal → App Registrations.

  • Tenant ID — your Azure AD directory GUID.
  • Client ID — your app's GUID.
  • Client Secret — app secret; keep it safe and rotate regularly.

Save To SentItems

Choose whether the sent email should appear in the mailbox's Sent Items folder.

Options: true or false. Default is typically true.

Examples

Microsoft Graph (recommended)

Example JSON payload (use your OAuth token when calling the Graph API). Replace the placeholders below with your real values. 

{
  "from": "noreply@yourdomain.com",
  "to": "user@example.com",
  "subject": "Test email from Graph API",
  "body": "<h1>Hello</h1><p>This is a test.</p>"
}

Example environment variables (do NOT commit these to source control): 

TENANT_ID="your-tenant-guid-here"
CLIENT_ID="your-client-guid-here"
CLIENT_SECRET="your-client-secret-here"

Use those values when requesting an OAuth token (example below).

Obtain token (example `curl`) & send

Replace `TENANT_ID`, `CLIENT_ID`, and `CLIENT_SECRET` with your real values. This example requests a client credentials token and demonstrates the values you need.

1) Request token (client credentials) 

curl -X POST "https://login.microsoftonline.com/TENANT_ID/oauth6/v2.0/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "client_id=CLIENT_ID&scope=https%3A%2F%2Fgraph.microsoft.com%2F.default&client_secret=CLIENT_SECRET&grant_type=client_credentials"

2) Use returned access_token to call Graph (pseudo) 

# Authorization: Bearer <ACCESS_TOKEN>
POST https://graph.microsoft.com/v1.0/users/noreply@yourdomain.com/sendMail
Content-Type: application/json

{
  "message": {
    "subject": "Hello from Graph",
    "body": { "contentType": "HTML", "content": "<p>This is a test</p>" },
    "toRecipients": [ { "emailAddress": { "address": "user@example.com" } } ]
  }
}

Security note: keep CLIENT_SECRET private. Use a secrets manager (Azure Key Vault, HashiCorp Vault, etc.) or environment variables on the server side — never embed client secrets in browser code or commit them to repositories.

Attachments & Templates

Attach files by mapping storage outputs or file inputs. Templates can be stored as HTML with placeholders (e.g., {{name}}, {{date}}). 

<h1>Report for {{date}}</h1><p>Hello {{name}}</p>

Test & Execute

  1. Fill required fields and save configuration.
  2. Click Save & Execute to send a test message.
  3. Check inbox and spam folder. Inspect logs for SMTP/Graph responses.

Troubleshooting

Common errors

  • 535 Authentication failed — check credentials or use App Password.
  • Connection timed out — verify host, port and outbound rules.
  • Relay denied — ensure SMTP relay is permitted.

Deliverability

  • Set SPF and DKIM for your sending domain.
  • Use consistent From addresses and avoid spammy content.
  • For high volumes use dedicated providers (SendGrid, SES).

Security Notes

  • Never store plaintext secrets in VCS or shared logs.
  • Prefer Azure Key Vault or equivalent for secrets management.
  • Use token-based auth where possible and rotate secrets regularly.

FAQ

Can I attach files?
Yes — via file input or mapping storage outputs.
How many emails can I send?
Subject to provider limits—check Microsoft 365 quotas.
How to debug?
Collect SMTP/Graph error codes, timestamps, and logs; share with support.

Contact & Support

For help provide:

  • Screenshot of settings (hide secrets)
  • Exact SMTP/Graph error message
  • Timestamps and recipient addresses
Read Outlook Email

Complete explanation of each input field used to fetch emails from Microsoft Outlook using Microsoft Graph API.

User Email *

The Outlook mailbox address from which emails will be fetched. Example: john.doe@yourdomain.com.

Sort Type

Determines the order in which emails are retrieved (based on received date).

asc (Ascending)

Pulls emails from oldest → newest. Good for historical processing.

  • Useful for incremental/chronological workflows.

desc (Descending)

Pulls emails from newest → oldest. Typical for checking recent activity.

  • Best for near-real-time monitoring and dashboards.

Size of Mail to Pull (Min: 1, Max: 1000) *

Number of emails to retrieve in one execution. Large values may increase runtime and hit throttling limits.

Tip: Start with small values (5–20) for testing.

Read Mode

Select which category/folder or state to filter when fetching emails.

All Mail

Fetches every email across the mailbox (Inbox, Sent, Drafts, Deleted, etc.).

Inbox

Fetches only emails in the Inbox folder.

Read

Fetches only emails marked as read (opened).

Unread

Fetches only unread (new) emails — great for processing incoming tasks.

Flagged

Fetches messages the user flagged/starred as important.

Sent

Fetches messages in Sent Items — useful for delivery/audit checks.

Drafts

Fetches messages saved as drafts.

Deleted

Fetches messages in Deleted Items (trash) — useful for recovery/audit.

Tenant ID *

Azure AD Tenant GUID that identifies your organization. 

TENANT_ID = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

Client ID *

Your App Registration's Client (Application) ID. 

CLIENT_ID = "yyyyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy"

Client Secret *

App secret used to authenticate with Azure AD. Keep this secret and do not expose it in public code. 

CLIENT_SECRET = "your-super-secret-key"

⚠ Never expose client secrets in frontend or public code.

Save

Saves the current configuration locally to the workflow but does not run it. Validates required fields first.

Save & Execute

Saves the configuration then immediately runs the read operation. Results and errors appear in Transaction panels.

Warning: Performs network calls — use small test sizes while validating.

Common Errors & Fixes

  • Authentication failed (401 / 400) — verify Tenant ID, Client ID, Client Secret and required Graph permissions (Mail.Read / Mail.ReadWrite).
  • Insufficient permissions (403) — grant admin consent for scopes or use delegated authentication.
  • Connection timed out — ensure outbound HTTPS to graph.microsoft.com is allowed.
  • Rate limiting — reduce batch size and implement retries with backoff.

Collecting Debug Info

  1. Record timestamp and transaction ID.
  2. Copy exact error messages and HTTP status codes.
  3. Note request parameters (User Email, Read Mode, Sort Type, Size).
  4. Attach verbose logs if available.

Security Notes

  • Never embed CLIENT_SECRET in client-side code or public repos — use Azure Key Vault or similar.
  • Prefer least-privilege scopes and token-based auth. Rotate secrets regularly.
  • Use TLS for all API calls and verify certificates.

FAQ

Can I read mail from shared mailboxes?
Yes — use the shared mailbox address (ensure your app or delegated user has access).
What fetch size should I use?
Start small (5–20) for testing; choose 50–200 for production while watching rate limits.
Can I filter by date or folder?
Yes — for advanced queries use Graph filters, e.g. filter=receivedDateTime ge 2025-01-01T00:00:00Z.

Contact & Support

When contacting support, include:

  • Screenshot of settings (mask secrets)
  • Exact error message & HTTP status
  • Timestamp and transaction ID
  • Request parameters (User Email, Read Mode, Sort Type, Size)
